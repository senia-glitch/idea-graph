# Этап 1 — спецификация (согласована 15.11.2026)

Статус: решения приняты, реализация не начата. Меняется только по явному решению пользователя.

## 1. Пакеты

| Пакет | За что отвечает |
|---|---|
| `idea-graph-core` | Граф карточек и связей, журнал, отмена. **Банки**: общий контейнер записей «тип, источник, версия схемы» в папке проекта; структуру записи задаёт пакет-автор |
| `idea-graph-engine` (выделяется из `shell`) | Всё про агентов без интерфейса: запуск Claude Code и OpenCode, сессии, инструменты агента, механики исследователей, совета, ревью и помощника, чтение деклараций этапов |
| `idea-graph-shell` | Только веб-сервер и интерфейс: холст, вкладка «Карта этапа», чат, настройки, отрисовка видов карточек из пакетов |
| `idea-graph-recon` («Разведка») | Сфера → список конкурентов → анализ → банк конкурентов |
| `idea-graph-processes` («Процессы») | Роли → сценарии → выбор → «как есть» с болями → вид автоматизации → «как будет». Модуль диаграмм внутри (в отдельный пакет — когда появится второй независимый потребитель) |
| `idea-graph` | Мета-пакет |

Принцип: делим не по технологии, а по причине изменений. Промпты и схемы остаются в пакете-этапе, механики агентов — в `engine`, вид — в `shell`.

## 2. Расширения платформы (контракт для этапов, фиксируется до реализации)
Этап описывается декларацией:
1. **Карта**: шаги (вопрос, вид результата, «ворота» утверждения).
2. **Виды карточек**: цвет, поля (текст, список, выбор, список ролей, диаграмма), как отрисовать.
3. **Помощник на шаге**: действия «предложить», «проверить» (независимое ревью), «уточнить» (согласованность), «сгенерировать»; вызывается в любой момент и не диктует запуск.
4. **Банки**: схемы записей, что шаг пишет и читает.
5. **Промпты** и критерии «достаточно».
Новый этап = один пакет, без правок `shell` и `engine`.

## 3. Карта этапа (вкладка «Карта этапа»)
Цепочка зелёных карточек-шагов, как на схеме пользователя. У шага: вопрос, статус, кнопка «Утвердить», кнопка помощника. Граф остаётся отдельным экраном с результатом.

**Разведка**
- R1 Сфера: пользователь пишет сферу (можно несколько; у каждой своё дерево).
- R2 Конкуренты: агенты ищут и дают список (название, ссылка, чем релевантен, тип: прямой / косвенный / аналог); потолок по умолчанию 6; пользователь правит список и утверждает кнопкой.
- R3 Анализ: после утверждения списка несколько агентов на разных моделях анализируют конкурентов (роли, бизнес-процессы, уникальные фичи) и пишут в банк с источниками. Сверка: берём, если подтвердили двое или есть ссылка.

**Процессы**
- P1 Роли: выбор из предложений (банк, помощник) или свои.
- P2 Сценарии: бизнес-процессы ролей, выбор из предложений или свои; диаграмма вариантов использования. Родитель сценария — сфера; роли связаны связью «участвует»; на графе у карточки сценария виден список его ролей (визуально, без лишних связей).
- P3 Выбор: какие сценарии автоматизировать (важность, частота, подсказка помощника по тому, что автоматизируют конкуренты).
- P4 «Как есть»: описание шагов текстом; агент строит диаграмму последовательности; независимое ревью; пользователь правит. Боли: пометки на шагах (что не так, как часто, чем это стоит, «Важность» из 4 уровней) и 1–2 строки итоговой проблемы по сценарию.
- P5 Решение: один выбранный вариант автоматизации на сценарий (из списка + своё; можно по шагам, не только роль целиком: убрать шаг, автоматизировать шаг, заменить роль системой, интеграция с внешним сервисом, уведомление, …); роли «Система», «БД», внешний ресурс; диаграмма «как будет» с подсветкой отличий.

## 4. Агенты
- **Исследователи** (3 слота, разные модели): веб-поиск и ресурсы пользователя.
- **Советники** (3 отдельных слота): совет для автоматического режима. Каждый независимо предлагает решение, один круг обсуждения (если единогласны — пропускается), общее решение. Обоснование записывается в карточку: 2–3 фразы человекопонятным языком, без пересказа переписки, особое мнение — одной строкой.
- **Ревьюер** (отдельный слот): независимое ревью. Не правит карточки, а оставляет замечания отдельными предложенными карточками; пользователь принимает или отклоняет.
- Автоматический режим остаётся (нужен хотя бы один начальный элемент; можно выбрать сферу), принимает решения советом, карточки остаются «предложена».
- Когда агент находит неточность в тексте (например, роль, которой не было на прошлом шаге), он уточняет детали и предлагает варианты решения.

## 5. Изменения ранее утверждённых шагов
Если меняется утверждённая карточка, помощник автоматически предлагает правки зависимых карточек: создаёт «правки-предложения», пользователь принимает или отклоняет. Ничего не меняется без решения человека.

## 6. Диаграммы
Хранятся структурой: участники и упорядоченные шаги «кто → кому: что» (+ тип шага, ссылка на боль или автоматизацию). Рисуются собственным SVG, экспорт в текст Mermaid для документации. Правка: таблица шагов и вставка текста с перестроением; перетаскивание мышью — позже.

## 7. Что принято по умолчанию (можно оспорить)
- Банк конкурентов живёт в проекте; один банк на проект, его читают все этапы.
- Виды карточек: «сфера» (корень, их может быть несколько), «роль», «сценарий», «диаграмма», «боль», «решение», «замечание», «правка». Старое «домен» → «роль».
- Прежний пакет `problem` (домен → сценарий → проблема → результат) заменяется этой парой этапов; до готовности «Процессов» остаётся как есть.

## 8. Порядок работ
1. `engine`: выделение из `shell`, декларация этапа, банки в `core`.
2. `shell`: вкладка «Карта этапа», ворота, помощник, отрисовка видов карточек.
3. `recon`.
4. `processes` с диаграммами.
5. Совет, ревью и предложения правок как механики `engine`.
