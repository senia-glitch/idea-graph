# Решения, принятые при проектировании

Этот документ — запись договорённостей, по которым построена система. Он нужен, чтобы
дальнейшие изменения не противоречили исходному замыслу.

## Зачем всё это

Предыдущая система (reqpipe) оказалась долгой, дорогой и некачественной: 27 холодных запусков
агента, весь JSON в каждом запросе, все этапы подряд, одна модель на всё, модель одобряла
собственную работу. Здесь всё наоборот:

- одна задача — один пакет; запускается только то, что нужно сейчас;
- у пакета одна живая сессия агента, в неё уходят только изменения графа, а не весь граф;
- модель выбирается отдельно для каждого пакета;
- то, что можно проверить кодом, проверяется кодом;
- проверяет и решает не та модель, которая предлагала.

## Граф

- Граф — отображение реальности. В нём только то, что есть на самом деле. Отклонённое удаляется,
  а не прячется. Важный отказ становится видимой карточкой-границей («Мобильное приложение не делаем»).
- Карточка: `id` (постоянный, не используется заново), `kind` (свободная строка; зарезервирован
  только корень «идея»), `title`, `body`, `status` («предложена» / «принята»), `author`,
  `decision` (вопрос, варианты, выбор, кто решил, обоснование, пометки «допущение» и «после спора»),
  `attrs` (свои поля пакетов).
- Связь: `{id, from, to, kind}`, вид свободный. Поля «родитель» нет: иерархия — это связь
  «детализирует» от потомка к родителю. Карточка может входить в несколько веток.
- Ядро проверяет только три вещи: один корень, связи ведут к существующим карточкам,
  идентификаторы не повторяются. Всё содержательное — дело пакета проверки.
- Граф меняется только операциями; у каждого изменения есть автор и номер ревизии. Журнал даёт
  «что изменилось с ревизии N», отмену и историю карточки.
- Правка человека главнее: если агент правит то, что человек изменил после последнего чтения
  графа агентом, ядро отклоняет операцию, и агент перечитывает граф.
- Агент читает граф как короткое оглавление с идентификаторами, а не как JSON.
- Граф лежит в папке идеи (`.idea-graph/`) и может вестись в git. Раскладка холста — отдельный файл.
- Прежде чем что-то предложить, агент сверяется с историей удалённого.

## Оболочка

- Агента и модель выбирает человек в настройках, отдельно для каждого пакета. Агентов запускает
  только оболочка.
- Один ход — один запуск агента с продолжением сессии. Способ запуска спрятан за адаптером.
- Инструментов у агента четыре: читать граф, менять граф, задать вопрос, завершить работу.
  Файлы и терминал закрыты; веб-поиск открыт только пакету, который заявил его в манифесте.
- Скилл — один текст для обоих агентов. Его передаёт оболочка при запуске; в папки скиллов
  агентов ничего не ставится.
- Правки графа, сделанные человеком, агент получает в начале следующего хода; сами по себе они
  агента не будят.
- Пакеты объявляют себя через точки входа Python и манифест.

## Уточнение идеи

- Один вопрос за ход, от двух до четырёх готовых вариантов, у каждого — последствие;
  рекомендация агента с причиной; можно ответить своим или отклонить все.
- Нерешённые вопросы — видимые карточки «открытый вопрос», не больше пяти.
- Агент может добавлять карточки без вопроса только со статусом «предложена».
- Когда уточнение закончено, решает человек; агент предлагает закончить, когда важных вопросов нет.

## Проверка

- Два слоя: код (сироты, круги, одинаковые заголовки, непринятые карточки, тяжёлые допущения)
  и модель (противоречия, дубли по смыслу, расплывчатость, пробелы).
- Находки — видимые карточки «замечание» двух уровней: «мешает» и «заметка».
- Простое исправление проверяющий делает сам после ответа; сложное оставляет карточкой
  «открытый вопрос» для пакета уточнения. Пакеты общаются только через граф.
- После первой полной проверки проверяется только изменённое и его соседи.
- Итог («чисто» / «есть_мешающие») считает код, а не модель.

## Решатель и автоматика

- Любой шаг может быть автоматическим по выбору человека. Пакет всегда только задаёт вопрос;
  кто отвечает — человек или решатель — определяет переключатель оболочки.
- Обычный вопрос решает один решатель. Важный — два вслепую, на разных моделях. Важность
  считается по графу без модели: затронут корень, три карточки и больше или карточка, от которой
  зависит много других.
- Разошлись — короткий спор (число кругов настраивается). Не сошлись — берётся решение, которое
  дешевле отменить. Спорного ответа не остаётся; на карточке видно «после спора» и обе позиции.
- Не хватило фактов — решение записывается как допущение. Веб-поиска у решателя нет.
- Решения человека неприкосновенны: вопрос, который их затрагивает, ждёт человека в очереди,
  а остальная работа идёт дальше.
- Предохранитель: после заданного числа решений подряд или суммы расходов автоматика встаёт на паузу.
- Любое решение агента можно переопределить; зависимые карточки подхватит следующая проверка.

## Компоновщик

- Карта — шаблон, общий для всех идей; состояние прогона лежит в папке идеи.
- Узел — пакет, стрелка — «после этого запускать то» с условием по итогу пакета; у стрелки есть
  предел числа проходов, чтобы петля не крутилась вечно.
- Модели в компоновщике нет. Режимы: по шагам и автоматически.
- Карта проверяется до запуска: неустановленные пакеты, неизвестные итоги, две стрелки на один
  итог, недостижимые шаги, карточки, которые никто не создаёт.

## Конец конвейера

Конвейер заканчивается передачей в pacage-studio-ide: пакет `idea-graph-handoff` пишет доску идей
студии (`studio-ideas.json`). Реализацию ведёт студия.
